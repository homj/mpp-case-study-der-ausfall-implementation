## Decisions

Choices made during implementation that are too small for an ADR. Include the reason.

- 2026-08-19: Open questions from `docs/case-study/analysis.md` §4 answered by the product owner: Q1 write path to Termino exists (assume; adapter + fake); Q4 location switch only as last resort, warning, never automatic; Q5 unknown patient = self-payer, keep in play, surface as data gap; Q7 automated email/SMS for automated actions, front-desk call as last resort; Q8 imminent appointment: offer same-time practitioner swap, never cancel right away; Q9 `prac_03` is a front-desk case, surface it. Q2, Q3, Q6 keep the original assumptions.
- 2026-08-19: Auto-rebook criteria (revised by product owner): qualifications must cover the service (hard gate), same location, start within ±2 days (explicit guess, one config value), gap fits, patient contactable. Same day no longer required.
- 2026-08-19: Cancellation notice for today goes out immediately only when the engine knows for sure same-day coverage is impossible (confirmed by product owner). Then auto-rebook within ±2 days if possible, else front-desk call.
- 2026-08-19: Aydin (`prac_05`, only other MLD45 practitioner) has zero free gaps on 09-07, 09-08, 09-09 → Hoffmann's MLD45 cannot be auto-rebooked even with the ±2-day window; she is the canonical front-desk-call case.
- 2026-08-19: Ubiquitous language: "therapist" renamed to "practitioner" everywhere to match the Termino data (`practitioner_id`). Glossary and all docs updated.

- 2026-08-19 (grilling rounds 1–2, product owner): absence has category + date-time range, default now→end of day; demo clock injectable and labelled "Demo"; exceptions first with quick actions, then automated actions with undo; undo = confirm dialog with reason, next step, pre-drafted message; channel = both SMS and email when available; unmatched patients (incl. fuzzy candidates) are labelled "unmatched", treated as self-payer, automation allowed, match resolved by the front desk (pick / search / create / keep unmatched / cancel if no valid patient); duplicate same-day appointments handled individually unless same date-time (data error), tasks bundled per patient; five prescription warnings; ingest 08:00 at start + button for 08:05; `tenant_id` now; explicit API service (Hono + zod contracts + OpenAPI) instead of TanStack server functions; web = TanStack Start + shadcn/ui + Tailwind v4; Node 24; TDD on the domain package; affected = overlap, in-progress appointments flagged and resolved in person (`completed` / `aborted`); statuses `open` / `in_progress` / `retry_contact` / `resolved`; resolutions rebooked / swapped / cancelled / kept / completed / aborted / resolved_externally; quick actions appointment-scoped except contact attempt; practitioner is blocked in Termino as soon as an absence is recorded; Termino writes use an outbox with retries and a `failed` state with manual fallback. ADRs 0001–0004 written.
- 2026-08-19: Time budget: about 80 minutes of the 3 h remain at the end of grilling. Build scope cut to the tracer-bullet slices in `docs/case-study/plan.md`.
- 2026-08-19 (slice 0, data + API layer): `tenants.id` **is** the tenant id, so the `tenants` table carries no separate `tenant_id` column; every other table has one and every query is scoped by it (ADR-0003).
- 2026-08-19 (slice 0): enum-like columns stay `text` with a TypeScript union instead of Postgres enums. A new value then needs no migration, and the type checker still guards every write.
- 2026-08-19 (slice 0): the seed skips a prescription whose `patient_id` is unknown and logs a warning, rather than failing the seed. All 557 prescriptions in the case data resolve.
- 2026-08-19 (slice 0): the ingest is idempotent by `export_id` and upserts appointments by their Termino id, so the newest export wins. Data issues are deduplicated by kind plus a key (`termino_practitioner_id` or `termino_patient_id`), so a second export does not create the same issue twice.
- 2026-08-19 (slice 0): export 08:00 produces three data issues: `unknown_practitioner` for `prac_03`, `fuzzy_match` for `pat_02538` (one candidate, same birth date plus phone or email), `unmatched_patient` for `pat_03115`.

- 2026-08-19 (slice 2, API use cases): `TerminoClient` and `Notifier` are ports in `apps/api/src/adapters/`. `FakeTerminoClient` applies every write to our own `appointments` table (optimistic state, ADR-0001): rebook cancels the original and inserts a row with id `apt_local_<uuid8>`; swap changes the practitioner; cancel sets the status; block is a no-op because we hold no bookable-capacity table. `FakeNotifier` only reports success — the outbox row is the record of what would have been sent.
- 2026-08-19 (slice 2): `deliverPending` orders pending rows with Termino writes before notifications, so a rebooking message never leaves before the write it announces (ADR-0001). Retries, backoff, and the circuit breaker stay out of scope; a failed row keeps `last_error` and the UI offers the manual fallback.
- 2026-08-19 (slice 2): a reschedule task is closed by the system (`resolved` / `resolved_by = system`) only when **every** appointment on it is an `auto_rebook`. One mixed patient keeps the whole task open.
- 2026-08-19 (slice 2): jsonb strips the `Date` type from a stored decision. The contract therefore states ISO strings everywhere (`decisionViewSchema`), and `reviveDecision` turns the strings back into `Date`s when a quick action needs a slot.
- 2026-08-19 (slice 2): every route parses its response through the zod schema from `@ausfall/contracts` before it returns. The contract cannot drift from the handler, at the cost of one parse per request.
- 2026-08-19 (slice 2): `POST /exports/ingest` takes a path relative to `DATA_DIR` and rejects anything that escapes it. The diff (`added`, `changed`, `cancelled`) is computed from a snapshot taken before and after the ingest, because `ingestExport` does not report it.
- 2026-08-19 (slice 2): the engine output for Anna Weber on 2026-09-07 matches `docs/case-study/analysis.md` §5 exactly — 14 affected appointments, 13 tasks, 11 auto-rebooks, Czerny `imminent_no_swap`, Hoffmann (MLD45) `no_slot`, Krueger a cross-location proposal, Kowalski's two same-day slots bundled into one task. `loadEngineInput` needed no fix.

- 2026-08-19 (reconciliation, ADR-0001): **local writes win until confirmed.** `ingestExport` takes `protectedAppointmentIds` and drops those rows from the upsert chunk entirely, so a protected appointment keeps its status, its slot **and** its `last_seen_export_id`. The ids come from the outbox (`listUnconfirmedTerminoWrites` → `protectedAppointmentIdsOf`: every `termino_write` that is `pending` or `delivered`). `packages/db` computes them itself by default — the outbox table lives in that package, so a direct query is simpler than threading the set through every caller — and `apps/api` passes the same set explicitly because its reconciliation needs the rows anyway. `apt_local_*` rows are never in an export, so they survive untouched.
- 2026-08-19 (reconciliation): the confirmation rule is one pure function, `reconcileWrites` in `apps/api/src/services/reconcile.ts`, tested without a database (`reconcile.test.ts`, 12 cases). It judges each unconfirmed write against the **export rows**, never against our own tables (ours already carry the optimistic result): `cancel` → the export row is `cancelled`; `swap` → the export row shows the new practitioner; `rebook` → the original is `cancelled` **and** a `booked` export row exists for the same patient, the new practitioner and the same instant. A confirmed rebook records `confirmedAs: <real Termino id>` and the local `apt_local_*` row is deleted, so the real booking replaces ours. Instants are compared as parsed times, not as strings.
- 2026-08-19 (reconciliation): a `block_practitioner` write is confirmed **at delivery**. No export reports bookable capacity, so waiting for evidence would leave it unconfirmed forever.
- 2026-08-19 (reconciliation): outbox state that has no column lives in the jsonb payload — `deliveredAt`, `deliveredAtExportCount`, `localAppointmentId` (the id the adapter minted), `confirmedAt`, `confirmedBy`, `confirmedAs`, `staleAfterExports`. No migration for a case-study feature. A write still `delivered` after two ingested exports gets `staleAfterExports: n`; `POST /exports/ingest` now returns `{added, changed, cancelled, tasksClosed, tasksAdded, writesConfirmed, writesUnconfirmed}`.
- 2026-08-19 (reconciliation): "resolved externally" now skips protected appointments. Only a change we did **not** make closes a task; our own optimistic write must never look like the front desk being off the hook.
- 2026-08-19 (verification, fresh database): absence → 11 `apt_local_*` rows, 11 rebook targets cancelled, outbox 11 `delivered` + 1 `confirmed` (the block). Ingesting 08:05 leaves all of that unchanged (0 flipped back) and reports `added 1, changed 1, cancelled 1, writesConfirmed 0, writesUnconfirmed 11` — the three genuine external diffs still show. A synthetic 08:10 export carrying our writes then reports `writesConfirmed 11, writesUnconfirmed 0`, retires all 11 `apt_local_*` rows and stamps `confirmedAs`; a further export without evidence stamps `staleAfterExports`.
